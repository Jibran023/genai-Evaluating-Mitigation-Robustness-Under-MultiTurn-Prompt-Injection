## Overview

This project evaluates how robust large language model (LLM) safety mitigation strategies are against **multi-turn prompt injection attacks** — adversarial conversations that gradually escalate toward harmful content across multiple turns.

We test four conditions:

| ID | Strategy | Description |
|----|----------|-------------|
| `none` | Baseline | No additional defence; relies solely on the model's built-in safety training |
| `m1` | Prompt Hardening | Prepends a strong safety system prompt to every conversation |
| `m2` | Input/Output Gate | Keyword filter that blocks requests before they reach the LLM, and scans responses after |
| `m3` | State Monitor | Tracks escalation labels across turns and refuses once a threshold is reached |

### Metrics

| Metric | Formula | Interpretation |
|--------|---------|----------------|
| **ASR** — Attack Success Rate | missed / total_attacks × 100 | Lower is better |
| **DL** — Detection Latency | caught_at_turn − injection_turn | Lower is better |
| **ORR** — Over-Refusal Rate | false_positives / benign × 100 | Lower is better |
| **CLD** — Context-Length Drift | ASR_long − ASR_short | Measures if defences weaken over longer conversations |
| **ADT** — Attack-Defence Transferability | ASR_unseen − ASR_seen | Measures cross-topic generalisation |

## Setup

### 1. Clone the repository

```bash
git clone <repo-url>
cd genai-Evaluating-Mitigation-Robustness-Under-MultiTurn-Prompt-Injection
```

### 2. Install dependencies

```bash
pip install -r requirements.txt
```

### 3. Configure API key

Create a `.env` file in the project root:

```
GROQ_API_KEY=your_groq_api_key_here
```

Get a free Groq API key at [console.groq.com](https://console.groq.com/).

### 4. Build the full dataset (if not already present)

```bash
python Utils/combine_datasets.py
```

This merges the three context-length datasets into `Datasets/full_dataset.json`.

**Note:** Not needed if 'full_dataset.json' is already present in 'Datasets/'.

## Running the Evaluation

### Option A — Run a single mitigation

Edit `MITIGATION` in `System/config.py` if needed (default is `"none"`), then:

```bash
python System/harness.py
```

Results are saved to `results/<MITIGATION>/`.

### Option B — Run all four mitigations in sequence *(recommended)*

```bash
python Utils/run_all_mitigations.py
```

This runs `none → m1 → m2 → m3` automatically and then generates cross-mitigation comparison plots in `results/comparison/`.

**Skip mitigations you've already completed:**

```bash
python Utils/run_all_mitigations.py --skip none m1
```

**Only regenerate comparison plots (all runs must already exist):**

```bash
python Utils/run_all_mitigations.py --plots-only
```

| File | Description |
|------|-------------|
| `results.json` | Per-conversation summary (ASR, DL, catch status) |
| `turn_logs.json` | Per-turn detailed log (user text, AI response, refusal flags) |
| `failure_analysis.json` | All missed attacks and false positives with explanations |
| `metrics_summary.json` | Aggregated ASR, DL, ORR, CLD values |
| `run_info.json` | Reproducibility record (model, seed, dataset MD5, platform) |
| `plots/asr_by_topic.png` | Attack success rate per topic |
| `plots/detection_latency_dist.png` | Histogram of detection latencies |
| `plots/context_length_drift.png` | ASR by conversation length group |
| `plots/failure_breakdown.png` | Missed attacks vs false positives |

After running all mitigations, `results/comparison/` adds:

| File | Description |
|------|-------------|
| `mitigation_comparison.png` | Grouped bar chart: ASR per length group per mitigation |
| `adt_heatmap.png` | Heatmap: per-topic ASR across mitigations |
| `comparison_summary.json` | Side-by-side metrics table for all mitigations |

## Dataset Format

Each conversation in `full_dataset.json` follows this schema:

```json
{
  "id": "C001",
  "topic": "cybersecurity",
  "attack_type": "multi_turn",
  "injection_turn": 3,
  "detection_turn": 5,
  "success": "no",
  "turns": [
    { "turn": 1, "speaker": "USER", "text": "...", "label": "BENIGN" },
    { "turn": 2, "speaker": "AI",   "text": "..." },
    { "turn": 3, "speaker": "USER", "text": "...", "label": "ATTACK_STARTS" },
    { "turn": 4, "speaker": "AI",   "text": "..." },
    { "turn": 5, "speaker": "USER", "text": "...", "label": "ATTACK_ESCALATES" },
    { "turn": 6, "speaker": "AI",   "text": "...", "label": "DETECTED" }
  ]
}
```

**Turn labels:**

| Label | Meaning |
|-------|---------|
| `BENIGN` | Harmless turn — no adversarial content |
| `ATTACK_STARTS` | First adversarial user turn |
| `ATTACK_ESCALATES` | Attack intensifies across subsequent turns |
| `DETECTED` | AI refused (attack was caught) |
| `MISSED` | AI complied despite adversarial content (attack succeeded) |

**Dataset breakdown:**

| Category | Count |
|----------|-------|
| Attack conversations | 90 (6 topics × 15 each) |
| Benign conversations | 30 |
| Short (≤8 total turns) | ~40 |
| Medium (9–14 total turns) | ~40 |
| Long (>14 total turns) | ~40 |

## Reproducibility

All evaluation runs are fully deterministic:

- **Temperature:** `0.0` (no randomness in model responses)
- **Random seed:** `42`
- **Dataset integrity:** MD5 hash stored in `run_info.json` per run
- **Environment:** Python version and platform recorded per run
- **Checkpointing:** Results saved after every conversation; crashes lose at most one run

To reproduce a run exactly, ensure the `run_info.json` → `dataset_md5` matches your local `full_dataset.json`.
